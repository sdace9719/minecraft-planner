### Blueprint for task type mine

## Inputs

- Item name and quantity.

## Pre-checks

- Check if the required tool is present in inventory or not. use constants/material-harvest.json to determine if tool is needed(hand ista mine is false) and if yes, check if it exists in the inventory. In case of tool missing, execute an fallback sub-routine to get that tool by generating a sub-plan for the tool and executing it. This plan will be generated by only supplying the tool name as input to the planner.
- If a tool exists, check if tool has enough tool durability. This means sum of expected junk blocks to mine + target block to mine should be smaller than tool durability. use ore-data.json to estimate junk block(if any). In case it exists but lacks required durability, execute the task with the same tool and once it breaks, re-queue the task again. This will re-trigger all the checks and should trigger creation of the tool.

## Execution Loop

- Calculate amount left to mine = current qty in inventory - input qty
- Execute baritone "#mine minecraft_item" command by calling the relevant endpoint on the controlbridge with try catch. Listen particularly for tool break event. The server's swagger doc should mention the relevant endpoint. This endpoint documentation should return this event as possible error, among others. when tool breaks, re-queue the task and set input qty as current-qty - expected_qty in inventory.
- The minecraft_item needs to be correct and needs consideration, in order to execute properly. For example, if we need to mine cobblestone, we should instead issue "#mine minecraft_stone" because mining stone without silk touch drops cobblestone anyway. Otherwise, it will hunt for cobblestone that generates naturally and depending on the biome, this command may fail altogether. Here is the  exhaustive list of mappings to remember.
    - Item to mine -> minecraft_item string name
    - cobblestone -> stone
    - Cobbled_Deepslate -> deepslate
- When the baritone command finishes without any errors, execute post checks

## Post Checks

- Verify if final item qty  = desired_item_qty as per the planner prediction. If no, then raise a fatal error by specifying task failed even though baritone completed successfully, and exit the python client.
